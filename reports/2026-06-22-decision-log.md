# Decision Log — ai-pokemon-red

## 1. TL;DR — The through-line

This project is **not about beating Pokémon Red**. It is a research probe for **one simple, generalizable, cheap agent that acts from the SCREEN ONLY** (no privileged RAM), built to climb a ladder from games to reality. The architectural bet is **dual-process**: `ai-pokemon-red` is the *world interface + System 1* (perception, the free reflexive fast loop, and a non-leaking RAM oracle), while `ai-aria` is *the agent + System 2* (reasoning, all memory, identity/constitution), reused unchanged across worlds. They meet at one **frozen** `SymbolicState`/intent seam (ADR-001). Four hard constraints are held on purpose — generalize, no-ROM, cheap (free autopilot does routine work; wake the LLM only at decisions), and a learning-boundary law — because they are what makes the result transfer. The project's hallmark is **reversing on evidence**: nearly every confident claim has been adversarially re-tested, and several were overturned.

### (c) Robustness-first pivot

- **Measure robustness with N runs, not 1.** *Why:* a 3-run cold batch scored 0/3 STARTER, exposing that single-run "successes" (#16 nav, #17 affordance) hid poor reliability. Meta-lesson: diagnose before fixing; free-validate every fix. (2026-06-21) **[HELD]**
- **REVERSE the "odometry is broken" hypothesis** (a 6-agent diagnosis showed `_best_shift` is sound; the high "miss" rates were artifacts — scripted Oak-drag teleports + scrolls dropped because cursor-advance gated on a directional token). *Why:* the real gap is BEHAVIORAL + an add-only occupancy map. **[REVERSED]**
- **Fix (commit 4f4878d): a repeated-no-move breaker (`_NO_MOVE_STALL=8` → steered wake) + self-correcting occupancy (a confirmed move CLEARS the traversed wall both ways).** *Why:* the autopilot jammed a blocked move 243× with no breaker, and add-only occupancy let a cutscene poison the map. PAID-CONFIRMED STARTER 0/3 → 4/5 (runs now cover 41-42 lab tiles vs 5-6). Raising the warp threshold 30→45 was tried and REVERTED (the warp/same-map bands overlap). **[HELD]**
- **Seen-states / NOVELTY signal (`core/novelty.py`):** detect stuck as REVISITING a state — count VISITS (rising-edge) to `(state_signature, screen_text)`; at 3 visits stop auto-advancing and defer UP to aria with a pure-fact `cycle_note`. Detection = System 1, response = System 2. *Why:* the Oak starter-dialog trap is a ~6-state CYCLE, not a frozen frame (a 1-step "did A advance?" check fails because text changes each press); rising-edge counting avoids false-tripping on a held textbox; a reflex can't depend on the resource it gates. PAID-VALIDATED (starter cold in all 3 runs; gate fired 11× on a freeze, quiet on a moving agent). **[HELD]**
- **General no-novelty STUCK-BREAKER** keyed on "decisions since the last NOVEL state" (`_STUCK_STALE=12`; self-clears on a real battle's fresh narration). *Why:* the nickname keyboard is a HELD state (44 identical frames = 1 visit) the cycle gate's rising-edge counting collapses; "since last novel" unifies a cycle and a persistence and is robust to `detect_mode` mislabeling the keyboard as battle. Free-validated (27× in the keyboard region, 0 false-fires in a real battle). **[HELD]**
- **Perception-escalation** (`--vision-escalation`): on a STUCK signal, call a strong VLM (Sonnet) to GROUND a confusing screen for the cheap aria agent (which still decides+acts); cached per state, per-run capped, spend folded into the cost cap. *Why:* the dual-process escalation tier applied to PERCEPTION. Sonnet IDs the keyboard correctly but still misreads the Gen-1 START mechanic — a grounding aid, not a solver. **[OPEN — built, not yet shown to change a paid outcome]**
- *(Affordance layer & battle line, validated en route to the pivot:)* **Battle confabulation fix = DECODE THE STATE, not nudge the prompt** (text-only + `decode_move_menu`/OCR; image OFF in battle); **battle settle = a sustained-static window** (`advance_until_static`); **battle auto-advance** (auto-A on narration, wake only at action/move menus, positive-ID-for-advance); **affordance layer** (motion-saliency ROIs + interaction-probe: face each wall, press A). *Why:* a cheap model builds a confident INVERTED world from low-res sprites that a nudge can't dislodge — the reasoning was never broken, the INPUT was; Oak/Pokéballs are non-walkable tiles that read as walls. Net result: run #17 got the starter cold and WON the rival battle; run #13 cut battle wakes ~68 → 18. **[HELD]**

### (d) Perception-architecture decision

- **Lightweight-vision probe findings:** the retro-sprite domain gap degrades fine-grained SEMANTICS across the whole spectrum (even Sonnet flip-flops species); what survives = localization, scene-type (CLIP), OCR/text. **CLIP is a PRECISION labeler, never the finder; RECALL is the open problem** (get it from temporal + behavioral signals). Best cheap labeler = **MobileCLIP2-S0** (9/10); the default ViT-B-32 was the WORST (5/10) — don't judge CLIP on its weakest variant. "ball" is the most FP-prone class everywhere. (2026-06-21) **[HELD]**
- **REJECT a CLIP-embedding spatial walkability store:** CLIP embedding captures APPEARANCE, not FUNCTION. *Why:* temporal split 97.7% is near-exact RECURRENCE (memorization); leave-one-MAP-out COLLAPSES (held-out lab 26.9% < 74.8% baseline; accuracy tracks cosine novelty). David reversed his own 97.7% "success" on the evidence. **[HELD]**
- **CONVERGED world model = an ONLINE behaviour-labelled tile→function map keyed by a cheap perceptual HASH (not CLIP);** CLIP/embedding reserved for NOVELTY detection only; **vision is ADVISORY** (typed-evidence precedence, never vote-fused); walkability stays movement-mono-source. *Why:* a hash matches the only thing that works — exact recurrence — deterministically, free and CI-testable (the "don't walk every cell" speedup); "more overlapping signals = more robust" is FALSE (vision signals are correlated failures). **[HELD]**
- **Split perception signals by RELIABILITY CLASS, not cheapness:** behaviourally-grounded signals COMMIT in System 1 (veto/typed-precedence); vision is surfaced with provenance, never weighted-voted. **[HELD]**
- **OCR = template-decoder DEFAULT + RapidOCR FALLBACK** (David FLIPPED from default-RapidOCR on evidence). *Why:* Gen-1 dialog/battle is ~90% of the text where the template is free and ~100% accurate. **[HELD]**
- **No frozen-contract change for the tile-map/vision work:** advisory predictions ride `spatial_memory` as additive keys; vision is quarantined in the escalation tier; calibrate vision OFFLINE vs the RAM oracle into constant tables. **[HELD]**

### (e) Tile-fingerprint build (task #7)

- **BUILD the tile-fingerprint tile→function map + novelty gate (`core/tilemap.py`):** 64-bit dHash fingerprint + behaviour-labelled observe/predict with confidence + Hamming-tolerant recurrence + `is_novel`, wired into the perceiver as ADDITIVE `spatial_memory` keys (frozen contract untouched). Scope = map + novelty ONLY (no autopilot change, no paid run). *Why:* free + deterministic validation showed the cheap hash beats CLIP on leave-one-MAP-out (81% cov / 84% acc vs CLIP 26.9%); Gen-1 indoor maps share a literal tileset. (2026-06-21) **[REFINED]**
- **Accept that appearance alone CANNOT perfectly determine function even within one tileset** — accuracy is FLAT ~92.5% across hash tolerance 0..12; the residual ~7% is intrinsic tile/function AMBIGUITY, not hash collisions; the behavioural veto + scene-conditioning are the levers. **[HELD]** *(later partly re-attributed — see Verification)*

### (f) Verification & correction

- **OVERTURN the strong cross-tileset hash claim** (a 5-agent verification). *Two laws established:* (1) aggregate accuracy LIES for navigation → measure **WALL-RECALL**; (2) hold out the whole **TILESET**, not one map. Honest leave-one-TILESET-out: INDOOR wall-recall = **0.0%** (449/449 walls miscalled WALKABLE @ conf 0.94). Root cause = an **all-zeros dHash ALIAS** (flat tiles → hash 0; 82% of miscalls) — a fixable fingerprint defect, NOT intrinsic ambiguity. *Why:* leave-one-MAP-out kept a sibling indoor map in the store, hiding the failure; indoor is ~70% walkable so calling everything walkable scored 80.7% > baseline while wall-recall was 0. (2026-06-21 night) **[REVERSED]**
- **The cheap-hash FIX (commit 1745096):** a richer key (horizontal + VERTICAL gradient + a 4-bit brightness BUCKET) with structured matching (intensity gated within ±1; Hamming tol on the 128-bit gradient only) + two consumer abstain knobs `predict(min_conf=, skip_flat=)`. *Why:* the brightness bucket cures the all-zeros alias (a flat dark wall and flat light floor no longer share key 0). Temporal acc-when-known 90.9% → 97.8%; indoor leave-one-TILESET-out wall-miscalls 449 → 2 with `skip_flat`. The residual is genuine physics (a flat tile can't be told wall-vs-floor by looks) — a coverage⇄safety DIAL, not a bug. Meta-lesson: look for the lossy COLLISION before reaching for a heavier model. (2026-06-22) **[HELD]**

### (g) Navigation-speedup (task #8)

- **Wire tile predictions into the autopilot:** `ExploreBrain` treats predicted-BLOCKED unvisited cells as SOFT-WALLS (skip the bump) with a two-pass FALLBACK (no useful frontier → ignore predictions & bump) and the behavioural veto authoritative; safe config = `use_predictions=True, skip_flat_pred=True`. NOT auto-enabled in the paid drivers (defaults off; agnostic worlds unchanged). *Why:* closed-loop A/B showed naive skipping STRANDS the agent (it learns "dark tile = wall," skips look-alike flat doorways/stairs, seals itself in: 42 vs 134 cells); `skip_flat` fixes it (explores 160 vs 134, bump-rate 27.9% → 18.0%). (2026-06-22) **[HELD]**
- **LAW: trust CLOSED-LOOP over offline metrics** — offline-on-fixed-trajectory evaluation is a CEILING; closed-loop testing is MANDATORY when the policy's outputs change its inputs. *Why:* `probe_navsave.py` said skipping avoids 76% of bumps, but only closed-loop (the agent's own sparse map feeding back) revealed the self-reinforcing strand; don't trust FLAT-tile predictions for navigation. **[HELD]**

## 4. OPEN / DEFERRED decisions

- **Paid validation of the whole tile-map line:** enable the safe tile-prediction config (`use_predictions=True, skip_flat_pred=True`) in the Pokémon drivers + a guarded PAID live run to confirm the nav speedup end-to-end (the standing NEXT). *Source: HANDOFF §2 NEWEST.*

- **Perception-escalation** built but not yet shown to change a paid outcome.

**DEFERRED (deliberate, with a planned revisit):**
- **Across-run / store persistence** (a cross-run tile→function map = across-run learning) — forbidden by the HARD LAW now; the "blank every run" law has a **PLANNED EXPIRY at It4** (an embodied agent in your house must remember the house). Revise deliberately, never by drift.
