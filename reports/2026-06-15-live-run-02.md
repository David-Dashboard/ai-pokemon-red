# Live run #2 — recorded, guarded, clean-start (2026-06-15)

_Companion to `2026-06-15-live-run-01-postmortem.md`. Run #1 failed (stuck in the house, ~$3).
Run #2 tests the fixes that came out of that post-mortem, on real hardware, with cost guarded._

**TL;DR — good news, then the honest next wall.** With the seam/portal fix + guardrails, the agent
**left the house, crossed Pallet Town, and reached Professor Oak's Lab** (4 maps, 57 cells) for
**~$0.23** — the run-#1 spatial failure is *solved on real hardware*. But it then **could not get the
starter**: the LLM flailed through Oak's forced dialog and, tellingly, **hallucinated its location**
("Viridian City", "Gramps", "Poké Mart") while ground-truth was Pallet→Oak's Lab. The bottleneck
**moved again** — from *spatial memory* to **semantic understanding of scripted events / menus**, plus
a **genuinely-missing memory-write channel** (so "record a lesson" is currently a no-op).

## 1. What we were trying to do

Run #1 (hybrid + aria/Haiku) never left the starting house and cost ~$3, woken 88% of steps on a
phantom-frontier thrash. This session we (a) **corrected the diagnosis** with a free oracle replay
(the *free* autopilot already reaches Pallet's doorstep), (b) **fixed the door-seam oscillation**
(portal), (c) added **cost guardrails** (progress watchdog + budget cap + a loop-breaker replan
nudge), and (d) built a **clean-start tool**. Run #2 is the paid validation:

> Does the agent now make real spatial progress at a **low, bounded cost**, and **where does it break
> next**?

Constraints honored (the north star): screen-only perception (RAM is a non-leaking oracle), the same
decoupled brain, cheap-by-default (free autopilot + wake-LLM-at-decisions).

## 2. Method

**Clean start (David's requirement — zero accumulated experience, archived first):**
1. `reset_aria_memory.py` **archived** the prior memory → `aria_memory_archives/iter-001_2026-06-15.zip`
   (67 KB), then **wiped** the run-generated experience (`journal/`, `memstore.db`, `usage.jsonl`,
   `earlier_today.json`), keeping the seed constitution + model caches.
2. Stopped → wiped → restarted `aria-app` so no in-RAM state from the prior 31 h survived.
3. **Verified clean:** the injected prompt dropped **6,128 → 3,257 tokens** (the accumulated memory is
   gone; only the seed constitution remains).

**The run (headless, recorded, guarded):**
```
play_pokemon.py --brain hybrid --backend aria --perception --load-state start.state \
    --record runs/run2.mp4 --max-llm-calls 30 --stuck-steps 60 --steps 400
```
Guardrails under test: the **portal** seam fix (`perceiver.py`), the **watchdog** (`--stuck-steps`),
the **budget cap** (`--max-llm-calls`, new), and the **loop-breaker** replan nudge (`HybridBrain`).

## 4. What worked, and why

- **The seam fix holds on real hardware.** Run #1's exact failure (never leaving the house) is gone.
  The free autopilot did **76 of 123 steps** — all the bedroom→house→Pallet→lab traversal — for $0.
  This is the iteration's core thesis (cheap local control + wake-LLM-at-decisions) validated live.
- **The guardrails did their job.** The budget cap halted cleanly at exactly 30 wakes (~$0.23); the
  watchdog stood ready; nothing thrashed. Run #1's ~$3 burn cannot recur unnoticed.
- **Cost is bounded and predictable.** Per-wake cost is ~$0.008 (unchanged, uncached) — the savings
  came from **far fewer wakes**, exactly as the free wake-rate estimate predicted.

## 5. What broke — the new bottleneck

**5a. The LLM hallucinates its location (semantic perception gap).** Ground truth was Pallet Town →
Oak's Lab. The model narrated "**Viridian City**", "**Gramps**", "**Poké Mart**" — places it never
reached. Geometric perception (walkability 99%, mode detection) is solved, but the LLM's *semantic*
reading of **where it is and what's happening** is unreliable confabulation. It's pattern-matching
generic building/dialog pixels to plausible-but-wrong Kanto locations.

**5b. It can't transact with a scripted gate.** Oak's forced dialog ("you can't go out, it's
dangerous!") pulled the agent into the lab — but the LLM **flailed**: it mashed A/B and tried every
direction (steps 80–103, 116–122) without grasping the actual task (let Oak finish → follow to the
lab → choose a starter). It never got a Pokémon. The agent can now **navigate** but cannot yet
**comprehend and complete** the game's story gates / menu interactions.

**5c. Gates are wake-expensive.** The forced dialog produced a burst of consecutive mode-wakes — the
overall rate (24.4%) was ~4× the free estimate (5.7%) purely because of this one scripted event. The
budget cap bounded it, but scripted events are both a capability gap *and* a cost spike.

## 6. The learning loop is still inert — and now we know exactly why

aria wrote **no lesson** this run (the tracked seed `lessons.md`/`core_memory.md` are byte-unchanged),
**despite** the loop-breaker nudge that explicitly told a stuck LLM to "record a one-line lesson."

Root cause (new, concrete): **the harness gives the LLM no memory-write channel.** `LLMButtonBrain`
parses only `THINK` / `MOVE` / `GOTO` from the reply — there is no action by which the model can
persist a lesson. So "record a lesson" is currently a **no-op instruction**. (aria's *automatic*
episodic memory did update — `journal/2026-06-15.jsonl` = 42 KB, `memstore.db` and `earlier_today.json`
rewritten — but the curated, recallable *procedural lessons* did not.) This is fixable: expose a
write-back action, or have aria distill lessons from its own journal between episodes.

## 7. Conclusions

1. **Run #2 is a success on its tested hypothesis.** The spatial-memory wall from run #1 is solved on
   real hardware: the agent reaches **Oak's Lab** cheaply (**~$0.23**, 30 bounded wakes), with the free
   autopilot doing all the walking. Caching is confirmed off but **not blocking** at this wake volume.
2. **The bottleneck moved, cheaply and on purpose.** For ~$0.23 we learned the next wall is **semantic
   perception + scripted-event/menu interaction** — the agent can go places but not yet *understand or
   transact* with them. The location hallucination (5a) is the headline finding.
3. **The learning loop has a concrete, addressable hole** (no write channel), not a vague "it didn't
   learn." That's a buildable fix.
4. **Process worked:** clean-start + archive + guardrails + record + oracle-verified analysis. The
   model's own narration was *wrong* about location — verifying against the oracle was essential.

## 8. Next steps

**Cheap / free first:**
1. **Give the agent a memory-write channel.** Parse an optional `LESSON: <text>` line (like `GOTO:`)
   and persist it to aria (or have aria distill `lessons.md` from its journal at episode end). Without
   this, every "record a lesson" nudge is theatre.
2. **Don't wake the LLM blindly inside a forced dialog.** Detect a *stable* dialog (mode=dialog with an
   advancing textbox) and let a cheap rule mash A to advance it, only waking the LLM at a **choice**
   (menu with options). This collapses the gate's wake-burst (and cost) and stops the flailing.

**The real capability gap (semantic):**
3. **Ground location/event semantics.** Options: a small fine-tuned/off-the-shelf classifier for
   "battle / dialog / menu / which screen", landmark text OCR for place signs, or feeding the LLM the
   *symbolic* event state instead of raw pixels. Pick the cheapest that kills the hallucination — this
   is the same "perception-as-a-module" move that fixed geometric perception in Iteration 02.
4. **Then re-run the Pallet→starter→Route 1 slice** (guarded) — success = obtains a starter and leaves
   Pallet, at a low wake-rate.

**Deferred:** prompt caching (aria-side; the unusual aria API path means it's its own investigation —
not blocking at this wake volume), and odometry drift (Tier-2; not blocking — the autopilot hands off
to the LLM at a healthy point).
