## What worked

- **Phase B navigation holds cold, end-to-end.** From the bedroom the free autopilot drove `38→37→0→40`
  and reached **Oak's lab by step 130** — past run #4's lab-entrance wall, with no map-lumping or
  ping-pong, on a cold start (not the run-#5 partial). The 15 productive wakes were the real decisions;
  ~180 overworld steps were free autopilot.
- **Dialog auto-advance engaged in the lab** — 81 of Oak's forced-dialog frames advanced for free, the
  same cost win as run #3, before credits cut it off.
- **The run-end auto-report hook fired correctly** (built this session) — `reports/2026-06-20-live-run-14.md`
  was written automatically with the oracle facts, wake/advance/error counts (incl. `errors: 65`) all
  correct. First live validation of the reporting infrastructure.

## What broke / the bottleneck

- **Anthropic credits exhausted at step 276** — the actual litellm error (read, not guessed):
  `"Your credit balance is too low to access the Anthropic API."` This is the **same recurring external
  dependency** that killed runs #5 and #6. It is NOT a harness or capability failure; the run was
  navigating and transacting Oak's gate correctly until the balance hit zero.
- **Secondary (a real harness gap the outage exposed): no API-error circuit breaker.** When aria began
  returning 400s, the harness retried every wake (litellm retried 3× each), surfaced the error as a
  `[wake:stuck]`, pressed the default `a`, and **counted each failed wake against the budget cap** — so
  a credit outage burned 65 of the 80 wake slots on no-ops before halting. A circuit breaker (halt after
  N consecutive *identical API errors*) would stop cheaply instead of grinding the cap.

## Addendum (2026-06-20) — all three "Next" items resolved; the real wall found

Run #14's three follow-ups are done, and the headline ("credits ran dry") turned out to be **masking**
the true downstream bottleneck:

1. **Anthropic credits topped up.** ✅
2. **API-error circuit breaker built + committed** (item 3, done first so the re-run was protected):
   the brain detects backend errors echoed as content (`_looks_like_api_error`) *and* exceptions, counts
   consecutive failures (`LLMButtonBrain.consec_api_errors`, reset on a real reply), `HybridBrain`
   forwards it, and both drivers halt at `API_ERROR_CIRCUIT_BREAKER=4` with the actual error. +4 tests.
3. **The end-to-end test was re-run as run #15** (`reports/2026-06-20-live-run-15.md`) with credits
   healthy and the breaker active. **Result: credits were NOT the only wall.** The agent again reached
   Oak's lab cold (`38→37→0→40`) but then got **wall-locked navigating the lab interior** to reach Oak —
   all 100 wakes `[wake:stuck]`, occupancy-map/pose corruption, never got the starter. **The downstream
   bottleneck is interior / short-range navigation (the deferred dead-reckoning drift)**, not credits.
   The breaker stayed correctly silent (0 errors) — validated as non-intrusive on a healthy run.

So run #14's "downstream inconclusive" is now **resolved**: with credits removed as a variable, the wall
is **in-lab interior navigation**. See run #15 for the full analysis and the next step (fix the
intra-room dead-reckoning drift — the precondition for the starter → rival → Route 1).
